lookahead sets of states

  • rules can't be reduced(as no complete items): [0..3], 8, [13..15], 18, [20..22], 26
  • state 4 has only one complete item(1 program → statements •), the item's lookahead set has one member, let's figure out's that member:
    1. start from state 0's core: `$accept → • program $end`
    2. a program can be a statements and program is followed by $end, so $end is a lookahead
    3. no other paths run to state 4
  • no lookahead set in need(as no shifts and no other reductions): [5..7], [10..12], 17, 19, [23..25], 27
  • state 9 has only one complete item and that item is empty; assume there are another item in this state which will shift, bison prefer shift; assume there are another item which can also reduce, that item's lookahead set shall conflict with this empty item's lookahead set(actually empty item's lookahead set contains everything), bison will resolve this conflict by checking which rule happens first
  • state 16: has complete items `7 uint8_hex → NUMERIC_STR •` and `8 num → NUMERIC_STR •`; will discuss later
